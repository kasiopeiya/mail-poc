# 起票先（リポジトリとルート Issue）

このファイルは2つを決める。ハーネスの問題を起票するリポジトリと、分解元の親が無い Issue を入れるルート Issue（Issue 階層の最上位の常設 Issue）である。読むのは `/link-root-issue` で、ルートの方針は [issue-policy](../policy/issue-policy.md) が持つ。

> [!NOTE]
> このファイルはテンプレート同期の対象外なので、書き換えてもテンプレート側の更新で戻らない。新規開発ガイドで起点 Issue（ガイドが要件定義書から作る、親が種別で決まる Issue）を作るなら、表の代わりに「issue-policy の標準のルートを使う」と書く（ガイドが標準のルートの名前、たとえば要件定義をルート名として渡し、ファイルに無い名前だと `/link-root-issue` が紐づけずに終えるため）。

## 振り分け条件

上の行から当て、最初に当たった行で決める。既定の行は最後に置く。条件は、ラベルや触るパスのように、外から見て分かる事実で書く。

| 条件                                                                                             | ルート     | ルートの本文（作るときに書く）                                                                  |
| ------------------------------------------------------------------------------------------------ | ---------- | ----------------------------------------------------------------------------------------------- |
| `broken-window` ラベル付き                                                                       | 改善       | AI が作業中に見つけた問題の Issue をぶら下げる常設 Issue                                        |
| 主に触るのが `docs/requirements.md` か、その入力元の `docs/project-context/input.md`             | 要件定義   | 要件定義書に関するタスクと、未決事項の解消の Issue をぶら下げる常設 Issue                       |
| 主に触るのが開発環境・技術スタック・アプリアーキテクチャ・ディレクトリ構成・`.github/workflows/` | 開発準備   | 環境構築・技術スタック選定・全体構造設計・CI／デプロイ経路の整備の Issue をぶら下げる常設 Issue |
| 主に触るのが `app/`・`infra/` のコードと、その単体テスト                                         | 設計・実装 | 実際のアプリ・インフラを作るタスクの Issue（機能開発の起点 Issue が中心）をぶら下げる常設 Issue |
| 既定（上のどれにも当たらない）                                                                   | その他     | どのルートにも当てはまらない Issue をぶら下げる常設 Issue                                       |

## ハーネスの問題の起票先

このリポジトリ（`kasiopeiya/mail-poc`）はテンプレートではなく、テンプレートの clone である。ハーネスの問題は、直す場所がここではなくテンプレート側なので、[`kasiopeiya/claude-dev-template`](https://github.com/kasiopeiya/claude-dev-template) に起票する。

- **ハーネスの問題**：原因が、テンプレートから同期されるファイルにある問題をいう。同期されるのは、`scripts/sync-template.sh` の `EXCLUDE_PATHS`（除外パス）に当たらないファイルと、`EXCLUDE_EXCEPTIONS` に挙げたファイルである。たとえば `.claude/` 配下の Skill・SubAgent・hook・Rule、`docs/policy/`、`scripts/`、`eslint-rules/` がある。パスの正は `scripts/sync-template.sh` である
- **このリポジトリに起票するもの**：除外パス側（`docs/project-context/`・`docs/design/`・`docs/adr/` など）と、`app/`・`infra/` のコードの問題である。原因がどちらか判別できないときも、このリポジトリに起票する（人間が見て振り分けられるため）
- **起票の仕方**：`gh issue create` に `--repo kasiopeiya/claude-dev-template` を付ける。ラベルの付け方と本文の書き方は `/quick-issue` と同じにする。このリポジトリのルート Issue には紐づけない（`/link-root-issue` の紐づけは行わない）。タイトルの段番号は、ブロッカーが無ければ `1.` とする。本文は、このリポジトリのコードを知らない読者が単独で読めるように書き、再現は Skill 名やファイルパスなどテンプレートにある部品の名前で示す

# 本プロジェクトの概要

- メール配信基盤を作成するPoC
- 利用者は社内のメール配信を行いたいシステムで、メール配信基盤はバックエンドAPIを用意してメール送信のリクエストを受け付ける

# 目的

- メール配信やAmazon SESの仕様や機能を理解すること
- 実際のプロジェクト開始前に落とし穴や重要な論点を把握すること

# 主な要件

- メール配信基盤は複数のメール配信サービスを利用する（SES・SendGridなど）
- 最初の利用システムはSESを使用するので、まずはSESだけで始める。ただし、ほかの配信サービスを後から足せる形にする
- 利用者は利用するメールサービスの選定をしなくても良いインターフェースにする（IFは抽象化し、どのメール配信サービスを使うべきかのロジックを基盤側で持つ）
- 自前の抑止リストを持つ
- PoCのため費用を最小限に抑える
- ドメイン認証などリアルな設定を実施する

# 想定利用システム

- 登録完了メールのような通知に利用予定、広告などではない

# 前提

- PoCのコードを本番にそのまま使うことはないが、一部を本番に使う可能性はある。そのため保守しやすく作り、将来の拡張を見込んだ形にする
- 将来、リアルタイム送信・一括送信（バッチ送信）も追加する見込みがある
- 本番の宛先は社外の一般ユーザー
- 最初の利用システムの送信量は、1日に数千〜数万通
- PoCは個人のAWSアカウントで行う。本番とは別のアカウントなので、サンドボックス解除と送信上限は本番に引き継げない

# 検証項目

各項目は「何が分かれば完了か」を満たしたら終える。

| 検証項目                                     | 何が分かれば完了か                                                                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 送信ドメインの認証（SPF・DKIM・DMARC）       | Route 53で取ったドメインに設定し、Gmailで受けたメールでSPF・DKIM・DMARCがすべてPASSになる                                                               |
| 受信箱に届くか                               | GmailとYahoo!メールのそれぞれで、受信箱・迷惑メール・届かないのどれになったかを記録した                                                                 |
| Gmail・Yahooの大量送信者の要件（調べるだけ） | 要件の一覧ができ、SESの機能で満たせるものとそれ以外に分けられる。日本のYahoo!メールに同じ要件があるかも分かる                                           |
| バウンス・苦情の通知                         | SESの試験用の宛先（メールボックスシミュレーター）でバウンスと苦情を起こし、通知が届き、その中身（ハードバウンスとソフトバウンスの見分け方など）が分かる |
| SESの抑止リストと自前の抑止リストの関係      | SESの抑止リストに、いつ・どの宛先が載り、どう外せるかが分かる。自前で持つ理由を一文で言える                                                             |
| バウンス率・苦情率による送信停止             | どの率で何が起きるかと、その率をどこで見られるかが分かる                                                                                                |
| サンドボックス解除の申請（条件付き）         | 解除しないと使えないSESの機能を使いたくなったときだけ行う。通ったか却下されたかと、審査で何を聞かれたかが分かる                                         |

# やらないこと

- 送信上限の検証
- SendGridとの違いの検証
- 携帯キャリアとOutlook.comでの届き方の確認（手元に宛先が無いため）

# その他

- ドメインはRoute53で取得予定（.linkなど安いものを使う想定）
